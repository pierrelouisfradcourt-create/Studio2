## OBSERVATION — Patterns externes comparables à runm_breakout

### Vue d'ensemble

Le projet runm_breakout est un casse-briques minimaliste pour le web, ciblant une boucle arcade-skill classique : paddler → casser des briques → recommencer. Trois jeux comparables offrent des architectures de référence à des niveaux de complexité croissants, du classique au roguelike moderne.

---

### 1. Breakout (Atari, 1976) — Archétype pur

**Mécanique centrale** ([Breakout - TV Tropes](https://tvtropes.org/pmwiki/pmwiki.php/VideoGame/Breakout1976)) : une raquette et une balle ricochetant sur un mur de briques. Le joueur pivote la raquette horizontalement, la balle rebondit aux angles variables selon le point de contact sur la raquette. Les briques disparaissent à l'impact et génèrent des points.

**Progression & économie** ([Breakout Wikipedia](https://en.wikipedia.org/wiki/Breakout_(video_game))) : tiered scoring (Yellow=1pt, Green=3pt, Orange=5pt, Red=7pt) + deux écrans complets à détruire. La raquette se réduit à 50% après avoir cassé les briques rouges, forçant la précision. La vitesse de la balle augmente à 4 hits, 12 hits, et au contact des rangs supérieurs.

**Boucles d'engagement** :
- **minute_1** : bounce balle, first brick destroyed, score appears, immediate feedback
- **minute_10** : clear screen halfway, ball speed increases noticeably, paddle control becomes skill-based
- **hour_5** : destroy full first screen, transition to second screen, raquette shrink event
- **endgame** : all 96 bricks destroyed = WIN / 3 lives lost = LOSE, game halts

**Raison du retour** : score fini (896 points max) crée un objectif clair ; simplicité masque une profondeur de trajectoire-prédiction ; chaque run court (5-15 min) encourages retry.

**Architecture supposée** : state machine simple (PLAYING, WIN, LOSE) + event-driven physics (ball collision, paddle position, score update) + render loop — zéro économie, zéro récompense non-observable.

---

### 2. Arkanoid (Taito, 1986) — Évolution avec complexité

**Mécanique centrale** ([Arkanoid Wikipedia](https://en.wikipedia.org/wiki/Arkanoid)) : même raquette-balle que Breakout, mais 33 niveaux avec variété de briques (certaines multi-hit, certaines indestructibles) + capsules power-up libérées aléatoirement (longer paddle, ball slow, extra life, multi-ball, cannon).

**Progression & économie** ([Arkanoid Wikipedia](https://en.wikipedia.org/wiki/Arkanoid)) : 33 niveaux à traverser linéairement, culminant à un boss (DOH). Chaque niveau possède sa topologie de brique. Les capsules introduisent de la volatilité : un joueur peut chuter rapidement sans les power-ups, ou dominer avec eux.

**Boucles d'engagement** :
- **minute_1** : learn paddle control, break few bricks, encounter first power-up capsule
- **minute_10** : master power-up juggling, adapt to brick variety (multi-hit vs indestructible), understand level layout
- **hour_5** : complete 5-8 levels, face escalating enemy patterns, build confidence in paddle reflexes
- **endgame** : reach DOH boss stage, defeat boss → game complete regardless of outcome (no continue on final stage)

**Raison du retour** : 33 distinct layouts prevent repetition ; power-up randomness encourages multiple attempts per level ; boss finale creates narrative closure.

**Architecture supposée** : level editor abstraction (brick arrays per stage) + pickup system (capsule spawning, collision detection) + enemy AI (DOH pattern) + progression tracker — encore zéro économie persistante, mais scaffolding pour la complexité.

---

### 3. Peglin (Red Nexus Games, 2023) — Roguelike pachinko

**Mécanique centrale** ([Peglin interview - TouchArcade](https://toucharcade.com/2023/09/11/pegilin-future-content-dlc-pricing-features-cross-save-steam-early-access-community-ports-interview/)) : pas de raquette fixe, mais un orbe tiré manuellement vers un plateau de piquets (pachinko-style). Chaque pique touché accumule des dégâts vers un ennemi. Les orbes diffèrent (déblocages progressive) ; les piquets spéciaux varient l'impact (reset, critical hit, débuff ennemi).

**Progression & économie** ([Peglin review - PC Gamer](https://www.pcgamer.com/be-a-little-pachinko-playing-goblin-in-peglin/)) : roguelike avec carte générée aléatoirement, combats alternés avec boutiques et événements narratifs. Deck-building : le joueur choisit quels orbes emporter, quelles reliques équiper (permanent power-up). Synergies émergent. Au niveau 20+, un mode Cruciball ajoute un handicap croissant à chaque re-run.

**Boucles d'engagement** :
- **minute_1** : aim orb, watch bounce, learn peg physics, first damage dealt
- **minute_10** : fight first enemy, manage orb choices post-combat, discover power-up synergies
- **hour_5** : complete 3-4 dungeon floors, adapt relics and orbs to enemy types, face mid-run bosses
- **endgame** : reach final dungeon boss, victory = complete run + unlock loot / defeat = death + reset to run start, Cruciball mode unlocks harder escalation

**Raison du retour** : procedurally random maps ensure no two runs identical ; deck-building creates replayability (theorycrafting builds) ; roguelike death + loot loops tap into incremental-progress dopamine ; high skill ceiling (aiming precision).

**Architecture supposée** : roguelike framework (dungeon generator, run state, death tracking) + pachinko physics (orb, peg, collision, scoring) + deck/relic system (persistent meta-progression) + enemy encounter AI — véhicule économie de reliques (meta-currency) et déblocages d'orbes par run.

---

|---|---|---|---|---|---|---|

| **Arkanoid** | Arcade progression | Static paddle | Ball + pickups | 33 levels linear | Powerups (transient) | 30-60 min |
| **Peglin** | Roguelike pachinko | Aiming mechanic | Orb bounce + physics RNG | Procedural dungeon | Relics + orbs (meta) | 15-45 min per run |

**Observations architecturales pour runm_breakout** :
- Breakout offre le **template minimal** : state machine, physics loop, render, no persistence needed.
- Arkanoid montre comment **scale par niveaux** sans explosion de système.
- Peglin démontre que la **mécanique pachinko-style** (vs pure paddler) reste engageante et ouvre un design-space alternatif (si exploration future).

**Briques candidates à l'import** (depuis knowledge_base ou jeux verts) :
1. Ball physics + paddle collision (Breakout-style).
2. Brick array rendering + hit detection (Arkanoid idiom pour variété).
3. Simple state machine (PLAYING → WIN/LOSE).
4. Score tracking + display (observable, non-persistent).

**Pièges connus** :
- Breakout se tue par ennui après 896 points (score fini) → runtime minimal mais satisfaction limitée.
- Arkanoid requiert **33 level designs distincts** → poids de création manuel, sauf si procédural.
- Peglin montre que roguelike + procedural = rétention accrue, mais complexité architecturale +3x.

Pour runm_breakout (minimal jouable), **Breakout template est le bon choix** : boucle claire, oracles vérifiables, pas de dépendance à l'économie.
