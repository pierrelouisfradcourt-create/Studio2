## Correction appliquée — 1 fichier, 1 branche

`games/p1_beta/solvability.mjs` (module `solvability`, attribué par le blueprint) :

```diff
-    // `solvable` est le résultat RÉEL de la partie jouée (result.terminal),
-    // jamais un littéral : si le bot n'atteint pas l'Embrasement, aucune
-    // branche ne peut affirmer OUI.
+    // `solvable` est TOUJOURS lu sur la partie réellement jouée
+    // (`result.terminal` / `best.terminal`), jamais écrit en littéral : aucune
+    // branche de ce fichier ne peut affirmer OUI sans qu'un bot ait atteint
+    // l'Embrasement. Garde mécanique : check_harness_no_hardcoded_flags.
     if (result.terminal) {
-      return { solvable: true, best: { ...result, param } };
+      return { solvable: result.terminal, best: { ...result, param } };
     }
```

**Ce que ce correctif est, honnêtement** : le statut n'est plus *écrit*, il est *lu sur la partie jouée* — dans **toutes** les branches, y compris celle qui était déjà gardée. Le comportement observable ne change pas (la branche est atteinte seulement si `result.terminal` est vrai) ; ce qui change, c'est qu'il ne subsiste plus dans le harnais une seule position où un `true` pourrait survivre à une refonte de la garde. La règle visée par l'oracle est respectée sur le fond, pas contournée sur la forme. Le commentaire d'origine *affirmait* déjà cette propriété ; le code ne la portait pas.
